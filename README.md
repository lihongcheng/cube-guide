# 魔方一步通

手机优先的三阶 / 四阶魔方还原游戏。上传六面照片，校对颜色，跟随中文说明和立体动画一步步还原，无需记忆公式。

**[在线试玩 → 魔方一步通](https://lihongcheng.github.io/cube-guide/)** · 无需安装，照片和求解数据只保存在当前浏览器。

## 本地运行

需要 Node.js 22.12+（本次开发环境为 Node.js 26）及 npm。

```bash
cd cube-guide
npm install
npm run dev
```

打开 <http://localhost:5173>。开发服务监听本机所有网卡，局域网设备可使用电脑的局域网 IP 访问。手机相机功能受浏览器权限与安全上下文限制；正式部署请使用 HTTPS，相册选择不依赖应用直接访问摄像头。

```bash
npm run build      # 类型检查与生产构建
npm run build:pages # 构建 GitHub Pages 的 /cube-guide/ 子路径版本
npm run preview    # 预览 dist，默认 4173 端口
npm test           # 数学、合法性、求解、投影与颜色测试
npm run test:production # 在 build:pages 后验证静态子路径及求解 Worker
```

浏览器端到端测试：

```bash
npx playwright install chromium
npm run test:e2e
```

若已有 Google Chrome，也可直接运行：

```bash
PLAYWRIGHT_CHANNEL=chrome npm run test:e2e
```

生产构建为静态文件，发布 `dist/` 即可，无需后端或密钥。Web Worker 文件与页面同源部署，不能直接双击 `index.html` 以 `file://` 使用。

[GitHub Actions](.github/workflows/pages.yml) 在 `main` 分支推送后运行单元测试、完整浏览器回归和 `/cube-guide/` 静态子路径验收，再自动部署至 GitHub Pages。首次发布前需在仓库 **Settings → Pages** 将 Source 设为 **GitHub Actions**；之后更新代码并推送 `main` 即会自动发布，试玩地址不变。

## 怎样玩

1. 首页选择 **三阶魔方 / 四阶魔方**。**先体验一下**使用相应阶数的打乱状态，体验真实求解、动画和通关流程。
2. **还原我的魔方**：按前、右、后、左、上、下的顺序导入照片。每个面有明确的上下邻面提示。
3. 拖动四角对齐魔方面，点击“识别颜色”。支持旋转、镜像和重新取图。
4. 选择画笔颜色，点击格子修正。三阶每面 9 格、共 54 格；四阶每面 16 格、共 96 格，也能全部手工录入。
5. 检查六面颜色和格子上方的邻面方向；方向不一致时直接整面旋转，保留手工校色。三阶可用六个中心格的实拍颜色重新分类（会重新计算颜色）；四阶没有固定中心，不提供此操作。
6. 合法性校验通过后生成路线。三阶按中心色对齐握法；四阶按准备页的前面 / 上面两张十六格图逐格对照。随后逐步观看并确认。
7. 只有点击“我转好了”才推进已确认状态。动画支持重播、慢速、拖动观察和正对目标面。
8. 最后检查实体六面是否同色，再确认完成。

拍摄期间可以整体转动魔方，**不能拧动任何一层**，否则六张照片无法描述同一个状态。

### 四阶使用提示

- 四阶校对页的“还原后的六面配色”指定最终颜色排列，默认白上、绿前、红右。它不是当前照片的中心颜色。普通魔方通常无需修改；特殊六色排列可逐面调整，选择已有颜色时两个位置自动交换。
- 四阶按完整 96 格求解，自动整理中心、配对棱块并处理 OLL / PLL 特殊状态，不需要打乱记录。
- 标注“两层”时，从指定面数，外侧两层捏在一起转，其他两层保持不动；半圈仍拆为两次 90° 确认。
- 还原中不要用某个活动中心格记方向。忘记握法时点“核对握法与六面”，按当前图案逐格找回。
- 首次四阶计算需准备查找表，可能持续几十秒；界面可取消，180 秒超时后保留照片重试。尚未测量手机真机耗时。
- 两种阶数独立保存照片、草稿、配色和进度；首页切换前立即保存。原三阶存储键和旧会话保持兼容。清除记录只影响当前阶数。

### 颜色已确认，但提示角块朝向不一致

“已确认六面”记录的是颜色确认进度；能否求解还取决于六面能否拼成一个合法魔方状态。每种颜色数量正确（三阶 9 格、四阶 16 格）也不代表一定可解。

在六面校对页点击 **检查照片方向**：程序在本机检查六张照片的全部 4⁶ 种旋转组合，展示可还原的候选。按候选的上边、右边邻面，与实物逐格核对（三阶同时可参考中心颜色）后，再点击 **与实物一致，应用此方向**。如果有多个候选，必须选择与实物一致的那个，程序不会自动采用第一个。检查通过后，“这就是我的魔方”即可使用。

每面也可以点“左转 / 右转”单独调整。采集页的旋转和镜像、校对页的旋转都会同步变换照片、四角框、颜色和置信度，不需要重新识别，不会丢失已经手工校正的颜色。

如果方向检查没有候选，单靠旋转照片无法修正。请继续核对照片是否放错面、镜像、重复拍摄或拍摄中拧过一层，并检查角落颜色；四阶还需检查最终配色。可点击 **导出诊断数据**，得到含阶数、54 / 96 格颜色、配色、面顺序和校验错误的 JSON，以便复现排查；其中不包含照片，也不会自动上传。应用仍会阻止对非法状态生成路线。

## 实现

- React、TypeScript、Vite；本项目实际使用 npm 和 `package-lock.json`。
- Three.js / React Three Fiber 立体模型；无 WebGL 时使用 CSS 立体模型，仍支持逐层动画和视角切换。
- 三阶使用 cubejs；四阶使用 MIT 许可的 @cubesmith/scrambler 0.14.1 内部状态求解器，来源及可复现生成方式见 [vendor 说明](./src/vendor/four-solver/README.md)。求解与查找表初始化均置于 Web Worker，支持取消、超时与错误恢复。
- 独立几何置换模型验证每条求解路线，不直接把求解输出视为正确结果。
- 三阶检查六色数量、中心唯一性、角棱组合、翻转/扭转和排列奇偶性。四阶检查 8 个有向角块、24 个有向翼棱、24 个中心色及角扭转和，不套用三阶的单组棱翻转和角棱奇偶限制。
- 独立 Worker 穷举六面照片方向，合法候选去重、预览并由玩家确认；旋转保留手工颜色与取景框。
- Canvas 四角透视取样、Lab 色彩距离分类、低置信度标注、中心颜色重新标定。
- 照片与颜色草稿存入 IndexedDB；紧凑的还原快照存入 localStorage，载入前重新校验路线和索引。
- 前端处理所有图片和求解，不发送照片、不接入第三方识别接口或埋点。

## 使用边界

- 当前支持普通六色三阶 / 四阶魔方；不支持其他阶数、异形和要求图案方向一致的魔方。
- 四角需要玩家调整，尚未实现自动检测魔方轮廓。曝光、反光、红橙混淆可能需要手工修色。
- 支持浏览器可解码的 JPEG、PNG、WebP。无法解码的 HEIC 提示先转换，每张照片限 20 MB。
- 应用跟踪的是**玩家确认后的预期状态**，不会通过摄像头自动判断实体是否转对。
- “上一步没转，误点确认”只撤销进度；“已转过，想退回”需要跟随逆向动画把实物转回。
- 不清楚实体状态时，应重新拍摄全部六面求解。
- 求解不保证最少步数；180° 拆成两个 90° 动作，显示步数按跟转动作计。
- 用时包括暂停和离开页面的时间，页面会明确标注。
- 照片会保留在当前浏览器，底部“清除本机数据”可删除；清除浏览器数据也会清除进度。

## 验证说明

单元测试覆盖 18 个标准动作与 cubejs 的独立对照、100 组固定种子打乱的求解回放、20 组任意照片方向恢复、非法状态、透视映射与颜色分类。浏览器测试覆盖演示通关、恢复与撤回、六张合成照片输入、手工颜色保留、方向候选与诊断导出、手机视口。

测试数量与生产版本浏览器验证结果见 [VERIFICATION.md](./VERIFICATION.md)。

合成照片测试用于验证上传、取样、颜色编码和求解连接的正确性，不能代替真实照片识别率。真实光照样本、实体魔方端到端、新手可用性、iOS Safari 真机测试仍需实测，不能据此声称已经验证。

求解器来源：[cubejs](https://github.com/ldez/cubejs) 与 [@cubesmith/scrambler](https://www.npmjs.com/package/@cubesmith/scrambler/v/0.14.1)，均为 MIT 许可。原始开发方案及四阶实现记录见 [DEVELOPMENT_PLAN.md](./DEVELOPMENT_PLAN.md)。
